# DECISIONS — ExecCal 行事曆

## 2026-09-30 — 標籤防呆用「正規化歸併」，不用「強制受管清單」

**決定**：標籤防呆採「正規化 key 比對」——`tagKey()` 做 NFKC 全半形轉換＋去空白＋小寫，變體自動歸到既有標籤；仍允許自由打字新增全新標籤。

**理由**：
- 使用者是內部少數人、MVP 邊測邊改，強制清單（要先到設定建立才能用）會拖慢輸入、增加操作摩擦。
- 正規化能擋掉最常見的分裂來源（大小寫/全半形/LINE Pay vs linepay），成本低、無誤合併風險。
- 刻意**不**做「數學 vs 數學課」這類近似字合併——語意不同，自動合併會製造錯誤統計。

**否決的選項**：
- B「標籤改為受管清單，只能從設定挑選」——防呆最強但摩擦最大，留待日後若仍見亂建再升級。
- C「模糊相似度提示（Levenshtein）」——易誤報、打斷輸入，效益不明。

**觸發升級的訊號**：若之後統計仍因標籤亂建而失準，再導入 B。

## 2026-09-30 — 人物拆成「主角×相關人物」，用新人物角色（非分類、非兩者並存）

**決定**：事件的人物拆成兩種角色——**主角（誰的行程）**與**相關人物（拜訪/參與/對象）**，
皆取自 contacts；event_contacts 加 `role`，contacts 加 `is_family`（標記可當主角的家人/本人）。
命名定為「主角／相關人物」。詳見 `docs/specs/人物角色-主角與相關人物.md`。

**理由**：情境是「大人幫小孩記行程、實際活動的是小孩」，需區分「誰的」與「見到誰」。
用人物角色最貼近使用者心智，且讓空檔聚焦（看誰的空閒）與財務（付給誰）各自乾淨。

**費用歸屬**：費用仍掛**相關人物（老師）**（finance_records.contact_id 不變）；
「依小孩」成本用 event→主角推導成報表維度，不改財務主鍵。

**否決的選項**：
- 主角沿用分類/行事曆——改動小但主角受限於分類顆粒度，且分類本是主題(公事/會議)非純人。
- 兩者並存（主角可人物或分類）——最彈性但選單與統計要兼容兩來源，易亂。

**風險**：需 db:push migration 到線上庫；分階段上（Phase 1 核心、Phase 2 統計）。

## 2026-09-30 — 衝突提醒放在「儲存前」而非「儲存後清單」

**選**：按儲存時就攔下，同一面板決定保留/刪除舊行程。
**不選**：儲存後才列「需記得取消的行程」——仍要使用者自己再去逐筆刪，正是 Peggy 怕忘的那步。
**細節**：刪除預設不勾（不可復原）；比對範圍為全部可存取分類（不受顯示篩選影響，避免藏起來的分類漏提醒）；
整日行程不算衝突；新增重複行程暫不比對。財務紀錄因 on delete set null 會保留。

## 2026-10-02 — 色盤只留色相不同的 10 色，不放同色系深淺版

**選**：10 個色相拉開的顏色。
**不選**：保留 24 色或同色系深淺版——視圖用 10% 淡底＋左色條呈現，亮度差會被淡化，深淺版在行事曆上幾乎分不出來。
**細節**：避開與衝突紅（#DC2626）相近的紅色；不做 DB migration，舊分類保留原色。

## 2026-10-02 — 月曆只有「跨日」行程畫橫條，單日整日行程仍是格內 chip

**選**：佔到 2 天以上才畫橫條。
**不選**：所有整日行程都放頂端橫條區（Google 做法）——單日整日行程放格內已夠清楚，先控制範圍。
**細節**：分層採「先開始、較長者在上」的貪婪排法；橫條不計入每格 3 筆上限。

## 2026-10-03 — 色盤用「同欄同色系、上鮮下深」兩排，而非任意加色

**選**：9 色系 × 鮮（約 600 級）／極深（800–900 級）兩種。
**不選**：加淺色（300 級）一排——淺色在 22% 淡底上幾乎變白，色條與時間文字也看不清。
**細節**：取代 10-02「只留 10 色」的決定；咖啡色改由下排金棕／鐵鏽承接；仍避開衝突紅。

## 2026-10-03 — 1對2 仍是「一行程一筆財務」，分給小孩的金額在統計時才攤

**選**：財務一筆（付給老師），存方案快照與我家上課人數，報表平均分攤給主角。
**不選**：每個小孩各存一筆財務——付款對象只有一位老師，拆筆會讓依老師對帳、預繳扣抵、編輯同步都變複雜。
**細節**：收費方案獨立成 `contact_rate_plans` 表（而非在 contacts 加 rate_1v2 欄位），才能支援 1對3、團班、漲價封存。

## 2026-10-03 — 收費方案不做「每人計價」與科目維度

**選**：方案金額一律是整堂總價；1對2 預繳共用一個帳戶扣。
**不選**：rate_basis（每人價）、各小孩分開預繳、科目維度——使用者確認不會和別家小孩共上、報價為總價、同一老師不同科不同價不會發生。
**細節**：日後需要時再加 rate_basis（預設 total），向下相容。

## 2026-10-03 — 收費方案不做封存；程式相容未套 0008 的庫

**選**：方案可直接刪改（財務有名稱快照與金額）；程式在 migration 前退回舊費率、寫入遇缺欄位自動重試。
**不選**：is_archived 封存——多一個 UI 狀態卻沒有實際需要；「先套 migration 才能推程式」——使用者要求改完即推，部署順序不能卡人。

## 2026-10-03 — 司機資訊存在 events 欄位、上車時間存「提早分鐘」

**選**：events 加欄位；去程上車時間＝開始時間 − 提早分鐘、回程＝結束時間。
**不選**：獨立 driver_trips 表或存絕對上車時間——行程改時間、重複行程各堂會對不上，且要多一套同步；MVP 也不需要指派司機。
**細節**：匯出以「複製純文字貼 LINE」為主（司機用手機），列印為輔；匯出範圍不受行事曆顯示篩選影響。

## 2026-10-03 — 依主角明細只顯示結清狀態，不提供勾選結清

**選**：結清只在「依老師」操作。**不選**：主角明細也能勾——1對2 一筆錢同時出現在兩個小孩底下，兩處都能勾容易誤以為各付一次。

## 2026-10-03 — 語音解析改用 claude-opus-5＋過去習慣，而非維持 Haiku

**選**：Opus 5（effort low）＋人物清單＋習慣摘要＋結構化輸出；系統提示詞快取。
**不選**：維持 Haiku——要同時對暱稱、人物角色、習慣、相對日期做推理，錯誤成本（漏記財務、漏交代司機）遠高於每次約 NT$1 的差價。
**細節**：可用 VOICE_MODEL 改回 claude-haiku-4-5；提醒採「模型問句＋伺服器規則」雙保險，重要缺漏不依賴模型判斷。

## 2026-10-05 — 月薪：每堂記 0 元＋每月手動記一筆，而非自動產生

**選**：每堂 0 元紀錄（保留堂數），月薪由使用者在報表按「記錄月薪」並可調金額。
**不選**：每月自動產生月薪紀錄——請假扣款、離職當月、提早結束都需要人判斷，自動產生反而要再去改；也不把月薪平均攤到每堂（堂數變動會讓每堂金額亂跳）。

## 2026-10-05 — 不同小孩不同價：方案綁「適用小孩」，而非在小孩身上設價

**選**：方案加 subject_ids，挑方案時主角完全相符優先。
**不選**：在小孩（人物）上設「各老師的價錢」——價錢是老師訂的，放老師底下設定才集中好找；也不另做「程度」欄位，因程度最終就是對應到某個小孩。

## 2026-10-05 — 標籤改名撞名時直接合併

**選**：改成已存在的名稱＝合併（行程改掛既有標籤、刪舊標籤），對話框先提示。
**不選**：另做「合併」功能或撞名時報錯——同義標籤整理是最常見需求，用同一個動作完成最直覺。

## 2026-10-05 — 固定作息存在人物上（jsonb），寒暑假用開關暫停

**選**：contacts.routine jsonb，多段作息、每段可停用。
**不選**：把上學建成重複行程——會塞滿月曆、干擾衝突提醒與報表；也先不做寒暑假日期區間與國定假日，避免範圍膨脹，看回饋再加。

## 2026-10-05 — 主角自動帶入用「分類名稱含家人名字」推斷，而非分類設定預設主角

**選**：比對分類名稱與家人名字，零設定。
**不選**：在分類管理加「預設主角」欄位——要多一個 migration 與設定步驟；目前分類名稱本來就是人名，推斷已足夠。名稱不含人名時不帶入。

## 2026-10-05 — 退回機制不可默默吞掉使用者設定

**選**：缺欄位時仍存行程，但對「使用者有設、卻沒存到」的欄位回傳警告並在前端顯示。
**不選**：完全默默略過（造成司機設定遺失、使用者不知情）；或直接存檔失敗（會擋住正常記行程）。

## 2026-10-05 — 刪除行程時連同費用紀錄一起刪

**選**：在 server action 中先刪該行程的 finance_records（含已結清）——刪行程代表這堂沒發生，費用不該留著。
**不選**：改 FK 為 on delete cascade（需 migration；程式端調整較靈活）；或在報表加刪除孤兒按鈕（治標不治本）。

## 2026-10-06 — 語音標題的人名後綴只加「主角」、由程式加

**選**：只加主角（＝非本人），由伺服器端程式組字串，已含名字就跳過。
**不選**：連相關人物（老師、外佣）也加——標題會變很長，且他們不是行程主人；交給模型在標題裡加——會不穩定、也可能和習慣標題疊成「打球-豪哥-豪哥」。

## 2026-10-06 — 主角名後綴在 server action 統一加，本人用名字判斷

**選**：在 create/update server action 加後綴（手動、語音都經過）；本人以名字含 Peggy／本人判斷。
**不選**：只在表單前端加——編輯改主角時容易漏、其他入口也不一致；在人物表加「本人」欄位——要 migration，目前只有一位本人，名字判斷已足夠。

## 2026-10-06 — 車程沿用「去程提早上車」分鐘數，回程假設同樣久

**選**：單一「單程車程」欄位（即原 driver_pickup_minutes），去／回各扣一次；只算在空檔，不改行程時間。
**不選**：新增去程／回程兩個車程欄位——要 migration、表單變複雜，目前沒有去回差很多的回饋；把車程寫進行程開始/結束時間——會污染行程本身與司機上車時間；依地址自動估——需地圖 API 金鑰與費用。

## 2026-10-06 — 預設提醒只套新增、整日行程不套

**選**：表單預設 10 分鐘前，整日自動改不提醒；既有行程不批次補。
**不選**：資料庫欄位預設 10（匯入等其他入口也會被套上、整日會半夜跳）；批次把既有未來行程補成 10 分鐘（Email 提醒會一次多出大量信件，先看新行程的感受）。

## 2026-10-06 — 手機提醒用 Web Push＋Supabase pg_cron

**選**：Web Push（免費、iOS 16.4+ 主畫面 App 也支援）；排程用 Supabase pg_cron＋pg_net 每分鐘呼叫，免外部帳號。
**不選**：LINE 通知（LINE Notify 已停止服務，Messaging API 超過免費額度要付費）；Vercel Cron（免費方案一天一次）；cron-job.org（要另外註冊帳號）；訂閱 ICS 到 Google 行事曆（Google 對訂閱的行事曆不跳提醒、更新要數小時）。

## 2026-10-06 — 行程對話框點外面不關閉

**選**：`onInteractOutside` 一律擋下，只能按 X／取消關閉——手機上誤觸外面的代價（語音行程重講）遠大於多按一下 X。
**不選**：維持點外面關閉＋關閉前確認（多一個對話框，手機上更容易誤按）；表單草稿自動暫存（較大工程，先看擋誤關後是否還需要）。

## 2026-10-06 — 語音多筆行程逐筆確認，不一次全存

**選**：拆成多筆後逐筆帶入表單確認，存好自動帶下一筆。
**不選**：一次全部直接存——語音辨識／解析錯誤會直接污染行事曆，且衝突提醒、收費帶入都在表單裡；一個表單同時編多筆——手機上太複雜。

## 2026-10-06 — 語音追問帶「表單現值」給模型

**選**：回答時把目前表單值一起送出，請模型只改相關欄位。
**不選**：只送原句＋回答重新解析——使用者手動改過的欄位會被蓋掉。

## 2026-10-06 — 指定日期不加 migration，rule 存 null＋共用 group

**選**：`recurrence_rule` 留 null、共用 `recurrence_group_id`，系列改／刪照舊可用。
**不選**：改 check constraint 加 'dates'（要 migration，且規則值對這種系列沒有實際用途）；每個日期各自獨立不成系列（之後要一起改時間會很麻煩）。

## 2026-10-06 — 相關人物依「主角情境＋系列數」排序

**選**：依目前主角找共同出現過的人，重複行程整個系列算 1 次；其他人依名字。
**不選**：整體使用次數（老師永遠第一）；只依名字（常用的要捲很久）；依分類（分類與人的對應不穩定，主角才是「誰的行程」的真相）。

## 2026-10-12 — 手機週檢視：7 天塞一頁，用「加高＋只放標題＋層疊」換可讀性

**選**：不左右滑、7 天均分；每小時加高到 64px、卡片只放標題、重疊改層疊（後開始的往右縮排疊上）。
**不選**：維持每天 6rem 左右滑（10/06 的做法，一次只看到 3 天，Peggy 要一頁看完）；照抄 Google（小字＋時間＋標題硬折行、重疊左右平分——Peggy 明確說看不出行程）；手機週檢視改成 7 列清單（看不出時段分布與空檔）。

## 2026-10-12 — 指定日期改用展開式多選月曆

**選**：點「＋ 加日期」在表單內展開 react-day-picker 多選月曆，可連續點多天。
**不選**：保留原生日期欄位＋呼叫 `showPicker()`（能修好但一次只能加一天，且各瀏覽器行為不一）；浮動視窗（Popover）月曆（手機上在對話框裡容易蓋住或跳出表單，之前標籤選單踩過）。

## 2026-10-12 — 學習回饋：AI 拆分＋確認、老師署名即時推算

**選**：送出時 AI 依小孩拆成「共同內容＋每人一段」（原文照抄），使用者確認後存進 `note_parts`；原回饋保留不動。署名老師即時由「財務對象 → 稱謂含老師／家教／教練」推算，不存欄位。英文名靠人物「別名」，拆分確認時自動學習。
**不選**：每個小孩各一個輸入框（Peggy 是整段從 LINE 貼上，每次手動切太麻煩）；AI 直接存不確認（對錯人會讓統計錯）；AI 用刪去法或猜測對應英文名（改在畫面上做刪去法，讓人看得到）；回饋另存「老師」欄位（換老師或補財務後會不一致）。

## 2026-10-13 — 語音相對日期：附日期對照表給 AI 查，不讓它自己算

**選**：使用者訊息附 14 週日期表（本週／下週／下下週…），規定一律查表；「隔 N 週」＝今天＋7×N 天。
**不選**：只在提示詞加例子（模型推算仍會差一週）；前端用規則解析「下下週三」（說法太多種，維護不完）。

## 2026-10-13 — 談話、開會不自動帶上課費（Peggy 的兩個選項選「預設不計費、可手動打開」）

**選**：AI 判斷 `isLesson`＋標題關鍵字；不是上課 → 財務預設關閉並說明，要算錢（例如當成上班時間的行政工作）自己打開，會照方案帶入金額。
**不選**：一律算行政費（要先有第 #4 題的工作分類時薪才算得準）；完全不讓這類行程記費用（有時確實要記）。

## 2026-10-13 — 語音確認：預設收起全部欄位，只看一句話

**選**：語音帶入時只顯示一句話摘要＋問題，按「沒問題，新增」直接存；要改再展開。
**不選**：維持完整表單（Peggy 回饋太多要看）；改成逐欄勾選確認（簡單行程反而要點更多下）。

## 2026-10-13 — 語音改／刪：一定先列候選讓人點選，刪除另外按紅色確認、修改走編輯表單

**選**：AI 只負責「找什麼＋改成什麼」，前端用搜尋找候選，使用者點選＋確認才動資料；修改帶入編輯表單，照樣檢查衝突。
**不選**：AI 找到就直接改／刪（同名行程很多，例如 Peggy 有週一、週二兩組「線上會議」，刪錯救不回）。
