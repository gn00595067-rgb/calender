# 手機推播提醒（Web Push）

狀態：已實作（2026-10-06），待套 0016、設環境變數、建排程後實測
日期：2026-10-06

## 問題
Peggy 問：提醒會不會像 Google 行事曆一樣在手機或任何裝置跳出來？
現況：瀏覽器通知**只在網頁開著時**才跳；Email 提醒寄給行事曆擁有者，但擁有者信箱是假的（boss@example.com），
而且排程端點被登入攔截（proxy 把 /api/cron 導到 /login），實際上從未寄出。

## 限制：只用免費資源
- 推播：Web Push（瀏覽器內建，免費）＋ `web-push` 套件。
- 排程：Supabase 免費方案內建的 pg_cron＋pg_net，每分鐘呼叫 `/api/cron/reminders`
  （Vercel 免費方案的排程一天只能一次，不夠用）。

## 設計
- 收件人：行事曆擁有者（＝Peggy 的帳號）登記過的所有裝置。每台裝置各自到「設定 → 手機通知」按「開啟通知」。
- iPhone：必須用 Safari「加入主畫面」，從主畫面圖示開啟後才能開通知（iOS 16.4+）。頁面有步驟說明。
- Android／電腦：Chrome、Edge 允許通知即可。
- 每筆行程只推一次（`events.reminder_push_sent_at`，與 Email 旗標分開）；編輯行程會重置，改時間後會重新提醒。
- 同一筆行程網頁開著時的瀏覽器通知與推播用同一個 tag，不會跳兩則。
- 裝置失效（取消通知、刪 App）推播回 404/410 → 自動刪除該訂閱。
- 頁面提供「傳送測試通知」。

## 資料（0016_web_push）
- `push_subscriptions(user_id, endpoint unique, p256dh, auth, user_agent)`，RLS 只能管自己的。
- `events.reminder_push_sent_at timestamptz`。

## 部署步驟
1. Supabase SQL Editor 套 `supabase/migrations/0016_web_push.sql`。
2. Vercel 環境變數：`NEXT_PUBLIC_VAPID_PUBLIC_KEY`、`VAPID_PRIVATE_KEY`、`VAPID_SUBJECT`、`CRON_SECRET`（值在本機 `.env.local`），加完要 Redeploy。
3. Supabase SQL Editor 建 pg_cron 排程（每分鐘 GET `/api/cron/reminders`，帶 `Authorization: Bearer <CRON_SECRET>`）。

## 不做（看回饋）
- 推給擁有者以外的人（例如被分享的人、司機）。
- 通知上的「延後 10 分鐘」按鈕。
- 修 Email 收件信箱（擁有者 email 是假的；有推播後 Email 優先度低）。
