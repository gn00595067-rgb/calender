# 司機接送：行程標記需要司機＋匯出司機時間表

狀態：已實作 MVP（2026-10-03），待套 migration 0009 後實測
日期：2026-10-03

## 問題與情境

有些行程（小孩上課、看醫生、應酬）需要司機接送。現在只能口頭或另外打字告訴司機，
容易漏掉、時間地點講不清楚。需要：
1. 在行程上標記「需要司機」，並記下接送方式、上車時間、地點、備註；
2. 一次把近期（例如未來 7 天）需要司機的行程整理成時間表，**直接貼給司機（LINE）或列印**。

## 審視鏡頭

- BA：解決「交代司機」的重複口頭溝通與漏接。不做 → 每週手動整理、容易出錯。
- PM：MVP 只做標記＋匯出；**不做**指派哪位司機、司機登入、司機確認回覆。
- SA：資料掛在 events 上（跟著行程走、重複行程可批次套用）；匯出頁只讀，重用 fetchEventsInRange。
- UX：司機多用手機 LINE → 主要按鈕是「複製文字」，排版用純文字、一行一趟；最容易錯的是
  去程上車時間 → 用「提早幾分鐘」自動推算，並在表單即時顯示「08:30 上車」。

## 資料模型（events 加欄位，migration 0009）

| 欄位 | 型別 | 意義 |
|---|---|---|
| needs_driver | boolean not null default false | 需要司機 |
| driver_trip | text check in (to, from, round) | 去程／回程／來回 |
| driver_pickup_minutes | int ≥ 0 | 去程：開始前幾分鐘上車（預設 30） |
| driver_pickup_location | text | 上車地點（去程起點＝回程終點），空＝「家」 |
| driver_note | text | 給司機的備註 |

- 存「提早幾分鐘」而非絕對時間：行程改時間、重複行程各堂都自動正確。
- 回程上車時間＝行程結束時間；目的地＝行程地點（events.location）。

## 各處設計

### 新增／編輯行程
「司機接送」開關 → 展開：接送方式（去程／回程／來回）、去程提早（0/15/30/45/60/90 分）、
上車地點（預設空＝家）、給司機的備註。下方即時預覽：「去程 08:30 從 家 → 台北醫院；回程 10:00 從 台北醫院 → 家」。
重複行程改「之後全部」時，司機設定一起套用（存在 events 欄位，走 commonFields）。

### 行事曆顯示
月曆 chip、週/日卡片、行程詳情顯示車子圖示；詳情列出去程/回程時間與地點、備註。

### 司機時間表（新頁 `/driver`，側欄「司機行程」）
- 區間：今天起 7 天（預設）／14 天／本月／自訂起訖。
- 範圍：所有可存取分類（不受行事曆顯示篩選影響，避免藏起來的分類漏交代）。
- 依日期分組，每趟一行：時間、去/回、起點 → 終點、乘客（主角，沒有＝本人）、行程名稱、備註。
- 「顯示行程名稱」勾選（預設開；不想讓司機知道內容時可關，例如看醫生）。
- 按鈕：**複製文字**（貼 LINE）、**列印／存 PDF**（列印樣式只印時間表）。

複製文字範例（來回拆成去程、回程兩行，司機看時間最直覺）：
```
【司機行程】10/6（二）～10/12（一）

10/6（二）
08:30 去程｜家 → 台北醫院｜小明｜回診｜備註：B1 等
10:00 回程｜台北醫院 → 家｜小明｜回診

10/8（四）
18:00 去程｜公司 → 晶華酒店｜本人｜應酬
```
- 列印：開新視窗只放時間表文字再呼叫列印（現有版面沒有列印樣式，避免印出側欄）。
- 行程沒填地點 → 目的地顯示「（地點未填）」，提醒補上。

## 不做（看回饋）
- 指派司機（多位司機時再加 driver_contact_id）、司機端登入/確認、自動推播。
- 依地址估算車程。

## 風險
- 需在 Supabase SQL Editor 套 0009；套用前程式照常運作（寫入遇缺欄位會去掉司機欄位重存，但司機設定不會保存）。
