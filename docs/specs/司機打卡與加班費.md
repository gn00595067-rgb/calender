# 司機加班申請與核准（原「司機打卡與加班費」）

狀態：第一版已實作（2026-11-13），待套 migration 0028 後實測；標 ❓ 的規則等 Elsa／Peggy／煒喻回覆
來源：Elsa 11/12 LINE 需求＋《司機薪資與加班費試算》＋ 11/13 Elsa、Peggy 回覆六個問題。

## 11/13 回覆後的方向調整
- **不做打卡**：Elsa：公司會有統一的打卡系統，司機在這裡只要有帳號登記行程。
- **改成「司機自己填加班 → Peggy 核准」**：Peggy：每天填有沒有加班、時間、事由（從哪到哪）。
  例：12/1 17:30–19:15 接送小孩上體操（17:50 出車、19:00 結束、19:15 送回）→ 下班 17:30 起就算，加班 1 小時 45 分。
- 兩人說法不同時以 Peggy（雇主）為準：核准制、司機看得到自己的加班費。

## 審視
- BA：每月算司機加班費靠口頭與試算表，容易漏、有爭議。改成當天填、Peggy 逐筆勾，有紀錄可對。
- PM：第一版＝司機帳號＋填加班＋核准＋月合計。不做打卡、薪資單、勞健保、GPS。
- SA：沿用老師帳號做法（人物管理建帳號，`contacts.driver_user_id`）；月薪沿用 `contacts.monthly_salary`；接送行程沿用「需要司機」的行程；國定假日讀政府行事曆。
- UX：司機只用手機：首頁看今天班表＋接送；送完已過下班時間會跳提醒「填今天的加班」，一鍵帶入時間與事由。最容易錯：忘了填 → 當天提醒；填錯 → 核准前可自己改／刪，退回後改完重送。

## 畫面
1. **司機頁 `/drive`**（司機帳號登入只看到這頁）：今天班表／國定假日；過了下班才送回的接送 → 黃色提醒「填今天的加班」；分頁「接送行程（7 天）／填加班／我的加班（月）」。
2. **司機加班 `/overtime`**（Peggy，側欄）：待核准（核准／退回＋原因）、已處理（可改回待核准）、月合計（加班時數 vs 46 小時、加班費、假日待確認筆數、預估薪資）、月薪設定。
3. **人物管理**：非家人人物多一塊「司機帳號」（建立／重設密碼／停用），訊息可直接貼 LINE。

## 資料（migration 0028）
- `contacts.driver_user_id`：司機登入帳號。月薪用既有 `contacts.monthly_salary`（空＝50,000）。
- `driver_overtime`：owner_id、contact_id、author_id、work_date、start_time、end_time、reason、event_id、status（pending／approved／rejected）、review_note、reviewed_at。
- RLS：主人全權；司機只看自己的、只能新增「待核准」、只能改／刪未核准的。
- `my_driver_links()`、`driver_trips(from, to)`：司機讀自己身分與主人「需要司機」的行程（不含費用）。
- 加班費不存資料庫，每次依月薪即時算（改月薪會影響當月顯示）。
